# 48 小时 FDE 实战：一份能追问到 SQL 的数据交付

> 某 AI 公司 FDE（Forward Deployed Engineer，前线交付工程师）岗位的限时实战题：48 小时内，用六份脱敏材料回答一个业务问题，并交出可运行的原型。
> 本文记录这次交付的**口径判断、证据结构与取舍**；材料为脱敏虚构数据，结论仅对本份材料成立。

---

## 一、任务形态

| 项 | 情况 |
|---|---|
| 时间 | 48 小时（含分析、报告、原型与提交） |
| 材料 | 六组脱敏材料 M1–M6：平台经营数据、人群画像切片、客服月报与差评、订单履约明细、专家访谈、数据口径与权限说明 |
| 业务问题 | 品牌 A 要推出面向 18–30 岁的新品牌，问「年轻人到底在意什么、钱从哪一环漏走」 |
| 交付物 | 分析报告 + 一页纸六栏 + 架构与风险说明 + 可运行原型 + 演示录屏 |
| 约束 | 数据多为人工导出、无 API；客户内网需要能离线跑 |

题目没有指定分析方法和结论，只给了业务背景。**这类交付的真实难点不在跑数，在于三件事**：口径不止一套、结论没有标准答案、用户对 AI 的信任是零。

## 二、开工第一件事：把口径说明当体检表

材料包里有一份《数据口径、获取方式、更新频率与权限说明》。它容易被当成背景资料跳过，但它更像一张体检表——逐条核对我对前五组材料的理解，核完发现：**直接上手算，至少有八处会算错**。

| # | 陷阱 | 材料里的表现 | 处理 | 不处理会怎样 |
|---|---|---|---|---|
| 1 | 金额单位「分 / 元」混用 | 某金额字段按分存储，最大值 251,871,670 | 先 ÷100，再与其他「元」字段比较 | 金额虚高 100 倍，ROI 全错 |
| 2 | 停播日被当缺数 | 直播明细只有 12 个有效场次，其余日期无有效直播 | 保留「未开播」为业务事实，不补零、不插值 | 场均被稀释，排期判断失真 |
| 3 | 投放跨零点残余消耗 | 消耗 0.36 元、ROI 6,400 这类记录 | 设消耗门槛（≥1,000 元）后再算 ROI，原记录保留 | 平均 ROI 被拉爆，结论反向 |
| 4 | 三组人群不是嵌套漏斗 | 「特定成交条件人群」推算人数大于互动人群 | 只比占比与跨场次差异，**不做相除** | 算出荒谬的转化率 |
| 5 | 人群数据是单月快照 | 只有 6 月数据 | 只写「当前结构」，不写趋势 | 用一个月证明「在变少」 |
| 6 | 月份错位 | 月报是 6 月，客户之声是 7 月下旬的人工样本 | 显式分开标注，7 月只作定性 | 拿 7 月冒充 6 月 |
| 7 | 表内行数 ≠ 月报口径 | 月报正文称 221 单，汇总 sheet 只有 162 行 | 只讲表内主题排序，不估总体比例 | 把抽样当全量 |
| 8 | 商品行 ≠ 订单 | 147,142 条商品明细 → 145,472 个主订单 → 131,358 个支付订单 | 分母一律取支付去重主订单 | 分母虚高 12%，所有比率偏低 |

## 三、同一个退款率，三个数都对

这是这次交付里最先要解决的分歧：6 月退款率，按订单算是 48.6%，按商品数量是 46.3%，按用户实付金额是 46.7%。开会时三个人报三个数，谁也说服不了谁。

| 口径 | 数值 | 分子 / 分母 | 回答什么问题 |
|---|---|---|---|
| 金额率 | 46.7% | 退款金额 ÷ 用户实付金额 | 钱回来了多少 |
| 商品数量率 | 46.3% | 退款数量 ÷ 商品数量（平台口径） | 货回来了多少 |
| 订单率 | 48.6% | 退款成功订单 ÷ 支付订单（6/1–18） | 人回来了多少 |

三个数都对，取决于问的是钱、货还是人。交付里默认用**订单口径**（要追到人和原因），谈钱时单独标注。

一处自查：本人最初算的金额率是 40.3%，分母用了含平台补贴的成交金额。补贴和优惠券不是用户掏的钱，退款时也不退给用户——拿含补贴的成交去除非补贴的退款，等于人为把率拉低 6 个百分点。换回实付金额后是 46.7%，与另外两个口径对上了，报告里已更正并写明原因。

## 四、结论怎么站得住：一条结论配三层证据

四条洞察按证据强度分开标注，不混着说。

| 洞察 | 主要数字 | 证据等级 |
|---|---|---|
| 退款漏在发货之后，不在发货之前 | 48.6% 的退款里 64.7% 发生在发货后（41,331 单）；发货前 17.2% | 强（全量、可去重复算） |
| 仓库问题解释不了这场退款 | 命中仓库工单仅 1,074 单（0.82%），即使全部退款也只占退款总数 1.7% | 强 |
| 新品牌不能直接继承品牌 A 的人群 | 曝光层 18–30 岁占 15.5%，18–24 岁从曝光 5.6% 掉到成交层 3.2%，24 场同场配对 24/24 同向 | 强（结构证据） |
| 退款是共性，不是某个坏商品 | 10 个主力商品退款率全在 44.8%–52.0%，中位 50.8% | 中强 |
| 用户不是嫌贵，是嫌「买完就降」 | 差评主题第一是平台优惠差价（24 条，占表内 14.8%），高于面料闷（10.5%） | 中（人工样本，不估总体） |

**排除干扰项是这一步的重点**。最常见的辩解是「发太慢所以退」：实测发货时长中位 6.6 小时、p90 18 小时，超时发货仅 2,400 单（1.83%），而超时订单退款率 24.9% 反而低于按时发货的 49.1%。物流这个解释在数据上站不住。

`发货后` 与 `收货后` 的区别也保留着：材料里只有发货时间、没有签收时间，所以全文写「发货后」，不往上推一格。

## 五、原型：数字必须能被追问到 SQL

四条洞察如果靠周报传递，三天就散了。所以把它们做成一个能跑的工作台——**ECHO 回声台**。

- 左边问一句，中间出洞察卡，右边拉出证据抽屉。
- 每张卡固定六件事：人群 / 场景 / 任务 → 结论 → 3 条证据（带来源）→ 置信度 → 还缺什么 → 边界。
- 证据抽屉四层：口径（分母、时间窗、避开哪些坑）→ SQL（完整可复制）→ 原始行（脱敏订单）→ 用户原声（标明来自哪份材料）。

核心原则只有一句：**取数层没有编数字的权限**——它输出的是 SQL，数字由数据库返回。任何一个数字被质疑，30 秒内能点开看到它是怎么算出来的。

另外四类真实阻力各配了一个机制：

| 阻力 | 机制 | 希望改变的行为 |
|---|---|---|
| 业务不想再填表 | 零录入 + 一键否决（认 / 不同意 / 记为待验证） | 从口头说一句变成留下可回溯的判断 |
| 看完就忘、没人推 | 早会三分钟，只推 3 张卡 | 从月度复盘变成每日 3 分钟 |
| AI 说的不敢信 | 证据抽屉：数字、SQL、原始行、原声全摊开 | 从「不信」变成「可以自己验一遍」 |
| 提了假设没人管 | 假设台账 + 待补证据，带归属人和验证方式 | 每条假设有主 |

## 六、一个刻意没做的取舍：不接大模型

这是这次交付里最值得写清楚的一点。48 小时交付的是**可运行的最小闭环**：`/api/ask` 目前是 7 条规则路由（关键词命中 → 执行预置 SQL），没有接大模型，也没有真正的 Agent 编排。报告里的「四个 Agent 分工」（口径守卫 / 归因分析师 / 证据链装订 / 假设台账）是**方案设计**，不是已实现的部分——报告里单列了一节写明「当前实现 vs 方案设计」。

这样取舍的理由是：48 小时内优先保证「数字可复现、演示不翻车、客户内网能离线跑」。

真要接模型，架构不变，只把入口换掉：**模型只负责把自然语言翻译成查询计划（选模板 + 填参数），不参与算数**；输出必须过白名单校验（只允许预置模板与受限参数）；超时或不合规则退回规则路由；每条回答附 SQL 与执行日志。一句话——**模型可以决定问什么，不能决定答什么。**

## 七、评审意见与修订

交付后收到四条评审意见，逐条处理后实测验证：

| 意见 | 处理 |
|---|---|
| 口径目录名写死，按说明原样跑会找不到文件 | 改为按文件名模式匹配，「隐藏」与「口径说明」两种目录名都实测通过 |
| 「Agent 只有查库权限」与实现有落差 | 报告新增「当前实现 vs 方案设计」，架构图页脚同步标注边界 |
| 后端写入缺输入净化 | 接口增加服务端净化（去标签、去控制字符、截断）+ 枚举校验，用评审同款手法（绕过前端直接写 HTML）复测拦截成功 |
| 置信度未说明标定方式 | 卡面标注，抽屉写明「置信度是人工标注的证据强弱，不是统计概率」，并给出三条标定依据 |

## 八、这次交付里可迁移的部分

1. **先问口径再算数**：分母错了，后面全错，而且很难被发现
2. **同一个指标有多种口径时，先说明它在回答什么问题**，而不是争哪个数对
3. **主动排除最常见的辩解**（物流、仓库、坏商品），证据才立得住
4. **证据分级**：强 / 中强 / 中，样本不足的地方写明「不能估总体比例」
5. **数字要能追问到 SQL**：取数层没有编数字的权限
6. **限时交付里，边界比完整更有价值**：写明「还缺什么」，比多塞一条没验证的结论有用
