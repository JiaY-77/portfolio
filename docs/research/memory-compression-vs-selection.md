## 写在前面

这篇不是综述。综述已有很好的版本（上面那篇论文就是），我不重复搬运。

这篇记录一件更具体的事：**我读完一份主流记忆研究框架后，接受了它的坐标系，但拒绝了它的一个操作定义，并说清为什么。**

我认为 "什么不值得做" 和 "什么值得做" 一样重要，甚至更需要讲清理由——因为它意味着你说过不，而不只是跟着做。

---

## 一、论文给了什么：一个能用的坐标系

这篇综述的价值不在论文清单（108 条论文链接、4 张数据集表、4 层工具表），而在一个二维坐标系：

**第一维：记忆分两种形态**

- **参数化记忆（parametric）**：隐式编码在模型权重里
- **上下文记忆（contextual）**：显式存在于外部数据，可为结构化或非结构化

**第二维：六个原子操作**

Consolidation（巩固）、Updating（更新）、Indexing（索引）、Forgetting（遗忘）、Retrieval（检索）、Condensation（压缩）。

这两个维度一交叉，就映射出四个研究话题：长期记忆、长上下文、参数化修改、多源记忆。

这个坐标系我非常认可。它把一个散乱的领域收敛成了可讨论的形状，而且我自研的系统在这六个操作里能逐个找到对应的实现——**说明这个抽象层级抓得准**。

## 二、分歧在哪：那个我拒绝的"压缩"

### 2.1 先看论文怎么定义

Condensation 在论文 v3 的原文定义是：

> **Condensation** enables efficient context usage under limited context window by retaining salient information and discarding redundancies with a compression ratio α before feeding it into models.

并且论文自己划了一条界线，把它和"巩固"分开：

> **Unlike memory consolidation**, which summarizes information during memory construction, compression focuses on reducing memory at inference.

也就是说：**巩固发生在写入时，压缩发生在推理时**。压缩的目的不是让记忆更好，是让记忆**更小、塞得进上下文窗口**。

论文进一步把它分为两种形态：

| 形态 | 时机 | 做法 |
|---|---|---|
| **pre-input compression** | 检索之前 | 把整段长上下文打分、过滤或摘要，塞进窗口 |
| **post-retrieval compression** | 检索之后 | 把召回来的内容再压一遍，或直接并入模型参数 |

### 2.2 我的拒绝理由

如果只做单轮压缩，这件事本身没什么问题——这一轮塞不下，压一压，用完丢弃，合理。

**问题在于把它作为记忆系统的常规操作，也就是层层递进地压。**

设想一下：

- 10 轮对话压成 1 条小结
- 100 轮压成 10 条小结
- 10 条小结再压成 1 条大结

`n` 轮之后，你手里只剩一条 `O(1)` 大小的东西，而原始信息量是 `O(n)`。

**每一次压缩都是有损变换。** 有损变换不可逆。第一层丢掉的细节，在后面任何一层都找不回来；而且随着层数加深，丢的对象从"具体措辞"变成"具体事件"，再变成"发生过什么"。

一个极端的推演：一个人活到 80 岁，每天的丰富经历层层压缩，最后可以精确地压成一句话——**"他出生过，活了 80 年，死了。"**

这句话在技术上是成功的：压缩比极高，token 极省，事实无误。但它已经不是记忆了。**记忆的意义恰恰在于那些在压缩中被丢弃的部分。**

### 2.3 论文其实也承认这一点

我拒绝这个操作，不是因为看不懂它的好处。论文自己在 Consolidation 一节里承认了风险，原文：

> robust long-term consolidation remains challenging — requiring the balance between stability and adaptability, **mitigating context loss from over-compression**, and preserving relevance under continuous updates.

`mitigating context loss from over-compression`——**缓解过度压缩带来的上下文损失**。

论文把它列为一个待解决的挑战；我把它当作一条不越的线。这就是分歧的本质：**不是技术判断不同，是对"记忆该是什么"的定义不同。**

## 三、那该做什么：不是压缩，是挑选

如果压缩走不通，上下文又确实有限，该怎么处理"记不下"这件事？

我的答案是：**挑选，不是压缩。**

这两件事方向不同：

| | 压缩 | 挑选 |
|---|---|---|
| 对内容做什么 | 改写它，让它变小 | 判断它，决定它的去留层级 |
| 是否可逆 | 不可逆，原始表述消失 | 可逆，内容本身不动，只动位置 |
| 判断依据 | 压缩比 α 和窗口大小 | 这条记忆**有没有被证明有用** |
| 失败后果 | 细节永久丢失 | 只是排错层级，还能找回来 |

**挑选的关键在于：用什么标准挑。**

我认为真正可靠的信号只有三个，且都是"事后证据"而不是"事前预测"：

1. **被检索到过**（`hit_count`）——说明这条记忆在实际查询里被需要
2. **被引用进回答**——说明它不只是相关，是被采纳了
3. **被使用者纠正过**——这是最强的信号，说明它重要到值得被专门否认

前两个是正反馈，第三个是负反馈但极高价值：**被纠正意味着这条记忆进入了使用者的核心关注区。**

而多数系统（包括我曾经考虑过的方案）用的是"事前预测"：让模型或规则判断"这段内容看起来重不重要"。这个做法的问题在于——**重要性是事后才知道的，事前判断必然不准。**

### 3.1 挑选的具体形态：分档，不删除

挑选不等于筛掉。我采用的形态是**分层平移**：

- **高价值**（被反复检索、被采纳、被纠正）→ 稳定保留在事实层，不随时间衰减
- **中等价值**（记录过程、一次性结论）→ 保留在日志层，按时间自然衰减
- **弱信号**（闲聊、确认、无信息量的往返）→ 快速衰减，但仍可检索到

核心原则：**内容不下架，只改变所在层级。** 原来在顶层的掉到中层，原来在中层的沉到底层，但**原文始终存在、始终可检索**。

这跟压缩的根本差别是：压缩是**信息量的单向下行**，分档是**注意力的位置调整**。前者让记忆变少，后者让记忆的读取顺序变好。

## 四、我对这份框架的完整取舍

既然要讲清"接受什么、拒绝什么"，就都列出来：

### 接受的

| 论文的操作 | 我的态度 | 理由 |
|---|---|---|
| **Consolidation**（写入时归纳） | ✅ 采用，但**只留可检索的痕迹，不取代原文** | 归纳成索引有用；用摘要替换原文不可逆 |
| **Updating**（冲突消解） | ✅ 采用并加强 | 双时间轴 + 显式取代声明 + 版本链，比"相似度超阈值就覆盖"更安全 |
| **Indexing**（索引） | ✅ 采用 | 关键词 + 向量 + 图谱三路并行 |
| **Forgetting**（遗忘） | ✅ 采用，但**只做衰减排序，不做删除** | 时间衰减调整的是排序权重，不是存活 |
| **Retrieval**（检索） | ✅ 采用 | 双路融合 + 图扩散 |
| **Condensation**（压缩） | ❌ **拒绝** | 见上文：有损不可逆，违背"记忆为连续性服务"的目的 |

### 我认为框架没覆盖的

论文把 Forgetting 主要描述为"忘掉"（衰减、unlearning），是**减法**。

而"挑选"是**留好的**，是**结构性的加法**——它不减少总量，它让重要的东西浮上来。

**这是框架的一个空白，不是我的落后。** 我认为下一代记忆系统的核心问题不是"怎么压缩得更狠"，而是"怎么更准地判断什么值得留"。

### 一个补充：框架的时代判断

论文发表于 2025 年 5 月，它关于"上下文有限"的表述反映的是那个时间点。

当时上下文窗口是硬约束，所以压缩的收益很直观。到 2026 年，长上下文已是常规配置，**"塞不下"这个前提在松弛**。

这意味着两件事：

1. **压缩的价值在下降**，因为它解决的问题正在变小
2. **挑选的价值在上升**，因为更大的窗口意味着更多的垃圾可以塞进来——**同样是"记不下"的另一种表现，只是从"物理不够"变成了"信号淹没"**

窗口变大不等于问题消失，问题的形态从"装不下"变成了"找不到"。

---

## 五、这件事对我意味着什么

我自研的系统里，六个操作有五个能落实，唯一的空白正是 Condensation——而我现在明确决定不补它。

这个"不补"不是能力不足的妥协，是**想清楚之后的取舍**。

我也认为，一个记忆系统的成熟度，不在于它实现了多少论文里的操作，而在于它**知道自己不该实现哪个，以及为什么**。
