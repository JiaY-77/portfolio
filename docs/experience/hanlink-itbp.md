# 工作产出说明：汉兴联（Hanlink）· ITBP（2026.08 – 至今）

> 本页记录本人在汉兴联（中国重卡与工程机械海外代理商，代理徐工、中国重汽等品牌，市场覆盖东非四国）实习期任 IT 业务伙伴（ITBP）期间的工作。
> 因涉及在职公司与客户信息，本页只讲**我怎么做、怎么想**，不涉及公司内部数据与业务细节。

---

## 一、我要解决的问题

公司业务在海外，组织却在多个国家铺开——东非四国（肯尼亚、乌干达、坦桑尼亚、卢旺达）加国内，**多法人、多时区、多制度**。人一多、地盘一散，管理就靠人盯：谁的年假怎么算、谁什么时候该续签、员工数据散在几个 Excel 里对不上。

我作为 ITBP 要做的，是把这些「靠人记、靠嘴传」的事，翻译成**系统能执行的规则**。

## 二、我的做法：把「业务的语言」翻译成「系统的语言」

ITBP 的核心动作，我理解是一个**双向翻译**：

- **业务 → 系统**：业务方给的是「我们这边年假是 28 天，司龄每满一年加一天」这种口语化描述。我要把它拆成：**字段（年假基数、司龄系数）+ 规则（按国家查表 + 加成公式）+ 边界（驻外人员特殊处理）**，写成开发能直接落地的需求。
- **系统 → 业务**：技术方案定完了，我得反过来用业务听得懂的话解释——为什么考勤要这么判、为什么权限要分两层，让业务方敢签字。

这套翻译难的不是技术，是**听懂业务没说出口的部分**：各国年假天数不一样（肯尼亚/乌干达 21 天、坦桑尼亚 28 天、卢旺达 18 天），还有司龄加成、驻外人员特例——这些都不是我设计的，是我**一项项问出来、拆出来**的。

## 三、我做了什么

以集团 HRM 系统（基于 Odoo 平台，覆盖招聘、组织、人事、考勤、薪酬五大模块）为主线：

- **需求与方案**：参与需求调研与方案设计，负责需求说明书关键章节撰写（约占全文 30%），全程参与 **67 张表的表结构设计**逐表评审与优化
- **多地区规则梳理**：直接对接东非四国 + 国内的 HR 负责人，把各国本地化规则（年假换算、多时区考勤判定、中英双语消息模板、9 类系统角色权限矩阵）**从口头描述拆解为系统可执行规则**
- **测试与验收**：作为测试负责人编写并执行系统测试用例，覆盖五大模块核心流程，对照需求说明书逐项验证、跟进缺陷闭环
- **跨职能协作**：作为业务方与开发团队（4 人）之间的桥梁，承接两边的需求澄清与对齐
- **系统集成**：参与 HRM 与钉钉 OA 的集成方案设计——组织架构/员工数据同步、审批结果回传、试用期与合同到期提醒、离职账号归档

## 四、这段经历让我想明白的一件事

**系统做得再怎么好，如果业务方不用、开发听不懂，就是废的。**
ITBP 的价值不在「我懂多少技术」，而在**让两边的人能对上话**。把模糊的需求变清晰、把专业的方案变好懂——这件事做熟了，跟 AI 领域里「把技术讲成客户听得懂的价值」是同一件事。

（顺带一提：这份工作也让我开始用 AI 工具给自己提效，后来延伸成了我给自己做记忆系统 Palimpsest 的动机之一——**因为我也需要「跨会话记不住」这个问题被解决**。）
