## 二、方法框架（我的产出骨架）

以下框架均为本人在实际工作中搭建并落地使用：

### 1. 客户诊断：从「流量思维」到「资产思维」

诊断报告的核心不是列关键词，而是回答一个问题——**怎么让 AI 在用户决策时主动推荐客户**。我把它落成三层结构：

- **核心判断**：GEO 的本质不是「买流量」，而是为客户**沉淀可被 AI 引用的信任资产**（技术证明 / 案例证明 / 安全证明 / 权威证明）
- **策略框架**：`5L 意图路径` —— 不按「关键词」覆盖，而按用户真实**提问场景**（认知 → 对比 → 决策）组织内容
- **执行流程**：分三阶段（信任基础构建 → 信任资产建设 → 验证与优化），每阶段有明确交付物与验收点

### 2. 竞品分析：先划清「技术边界」，再谈「路径差异」

这份分析的出发点不是罗列竞品功能，而是先回答**行业共同约束**：

- 所有 AI 搜索平台都基于 **RAG 架构**（检索 + 生成），检索过程**不可解释**——这是技术范式的固有约束，**没有服务商能干预平台底层算法**
- 因此各家竞品的差异，不在「谁能改变算法」，而在**在共同约束下选择了什么内容适配路径**

在这个认知之上，再拆解竞品各自的能力定位与差异点，最后收敛到我方产品的差异化方向。
（这份分析的判断：**先定义「什么做不到」，再谈「做什么」**——避免用无法兑现的承诺做市场定位。）

### 3. 产品文档：对外讲价值，对内讲边界

- **产品介绍文档**：面向客户的营销叙事（痛点 → 价值 → 方案 → 案例），多版本迭代
- **产品培训文档**（内部）：面向销售的实战口径，含话术与常见异议应对
- **API 接入指南**：面向开发者的技术文档（认证 → 参数 → 响应 → 错误码 → 代码示例 → 常见问题）
- **报价方案**：分档套餐设计（档位、服务内容、价格梯度、适用场景）

### 4. 市场调研：用「对比框架」代替「价格罗列」

海外 vs 国内的模型 API 价格调研，不是抄一张价格表，而是建立**可对比的分析框架**（价格悬殊 / 企业折扣 / 性能生态 / 长文本成本），并从中导出**对业务的可执行建议**（定价策略 / 采购方向 / 销售话术）。
