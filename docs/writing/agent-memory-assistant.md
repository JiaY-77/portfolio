## 一个具体的难受

我用了快一年的 AI 编程助手。真正让我难受的，不是它不够聪明——模型一代比一代强，做题、写代码、查问题，能力早就够用了。

难受的是：**每次开新会话，我都要重新交代一遍。**

项目在哪个目录，用哪个解释器，哪些坑已经踩过了，我不喜欢什么样的写法，上次那个方案为什么被否掉。交代完，十分钟过去了。第二天再来一遍。

这件事靠「能力」解决不了。模型再强，它对我知道的仍然是零。

## agent 和 assistant 差在哪

我现在的判断是这样：

- **agent** 的完成度看「任务完成率」——能不能把这件事做完
- **assistant** 的价值看「我需要解释多少」——它是不是已经知道我在干什么

这是两个不同的评价轴。市场上的工具几乎都在第一个轴上竞争：能调多少外部服务、能跑多长的任务、能接多少个 MCP 服务器。很少有人认真做第二个轴。

但「懂你」这件事不是态度问题，是**数据问题**。没有关于你的历史，谁都懂不了你。

## 连续性有三层，大多数产品只做了第一层

我把它拆成三层：

| 层级 | 是什么 | 现在谁在做 |
|---|---|---|
| 会话内 | 上下文窗口 | 所有产品都在做，且做得越来越好 |
| 跨会话 | 上次聊到哪、哪些结论定了 | 少数在做，多是「总结 + 塞回 prompt」 |
| 跨工具 | 同一个你，在 A 工具里说过的事，B 工具也知道 | 基本没人做 |

第三层才是关键。因为我不会只用一种工具：写代码用一个、查资料用一个、做文档用一个。如果记忆绑在工具上，那我的「连续性」就被切成了几段。

所以我把这件事当成一个系统的需求来做：一个宿主无关的记忆层，谁的客户端都能接。

## 记忆不是聊天记录

这是我做 Palimpsest 时最早定下来的一条：**聊天记录是流水，记忆是事实及其演化。**

区别在于「改」：

- 流水只会追加，越堆越长，找东西靠翻
- 事实会变——上周说服务监听 8090，这周改成 8095。流水里两条都在，谁也不知道哪个还有效

所以记忆系统最难的不是「存」，是**什么时候该覆盖、什么时候该保留、改错了能不能查回来**。

我的做法是：新事实覆盖旧事实，但旧的不会被删掉，而是标记为过期、用一条版本链（`REVISED_BY`）指回新的。这样「这个事实是怎么一步步变成今天这样的」永远查得到。

覆而不失，改写可溯。

## 这个等式我还没证成

说「agent + memory = assistant」是有点大言不惭的。更准确地说，这是我的一个假设：

> 如果 agent 和 assistant 的差别在连续性，那补上连续性，就该更接近 assistant。

怎么验证？我在找可测的量：

- 同一类任务，跨会话时的**上下文重建时间**
- 我为了纠正它而说的话的**次数**
- 以前的结论被**重复推翻**的比例

现在只能测我自己：以前每次开新会话先花几分钟交代背景，现在这一步基本没了；以前同一个偏好要说好几遍，现在说一次它记得。

这算不算「变成 assistant」，我说不准。但确实让我少解释了很多——这就够我先继续做下去。
